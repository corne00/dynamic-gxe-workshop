8 · Pitfalls

Three ways the method can mislead, each shown on this data

1 · A library that cannot express the target

So far the response was biomass, which grows roughly as a smooth function of the season. Now try the same pipeline on leaf area index (LAI), which rises, peaks, and then falls as leaves senesce. We only change var = "lai".

trl <- make_trajectories(traj, drv, var = "lai")
gl  <- gram_stats(Theta, trl)
cvl <- cv_blocked(Theta, trl, gl, fit_ols)                 # cubic polynomial library, all 13 terms
round(evaluate(cvl$pred, trl), 3)
trajectory_rmse  fixed_day_rmse   maturity_rmse 
          0.885           1.212           0.972

Compare with the lookup (the genotype’s mean curve in other years), and with a different library: a B-spline basis in thermal time, which is flexible in the season clock, plus the other drivers linearly.

lookup_all <- function(tr_) {
  base <- array(NA_real_, dim(tr_$Y))
  for (y in seq_along(tr_$years)) base[, y, ] <- apply(tr_$Y[, -y, , drop = FALSE], c(1, 3), mean, na.rm = TRUE)
  for (g in 1:dim(base)[1]) for (y in 1:dim(base)[2]) {
    v <- base[g, y, ]; ok <- which(!is.nan(v)); v[is.nan(v)] <- v[max(ok)]; base[g, y, ] <- v; base[g, y, 1] <- tr_$Y[g, y, 1] }
  base
}
df <- 6; TT <- drv$U[, , 1]; B <- bs(as.vector(TT), df = df)
Th_spl <- array(NA_real_, c(dim(TT), 1 + df + 3), dimnames = list(NULL, NULL, c("1", paste0("B", 1:df), "DL", "RAW", "RAD")))
Th_spl[, , 1] <- 1
for (j in 1:df) Th_spl[, , 1 + j] <- B[, j]
for (j in 1:3)  Th_spl[, , 1 + df + j] <- drv$U[, , j + 1]
cvs <- cv_blocked(Th_spl, trl, gram_stats(Th_spl, trl), fit_ols)

res <- rbind(`cubic polynomial` = evaluate(cvl$pred, trl), `B-spline in TT` = evaluate(cvs$pred, trl), `no-weather lookup` = evaluate(lookup_all(trl), trl))
round(res, 3)
                  trajectory_rmse fixed_day_rmse maturity_rmse
cubic polynomial            0.885          1.212         0.972
B-spline in TT              0.526          0.664         0.539
no-weather lookup           0.473          0.687         0.637

The summary table hides when each model is wrong. The error of every held-out trajectory, by day:

lk <- lookup_all(trl)
err_by_day <- function(P) sapply(2:dim(P)[3], function(d) { ok <- !is.na(trl$Y[, , d]); sqrt(mean((P[, , d][ok] - trl$Y[, , d][ok])^2)) })
nd <- dim(trl$Y)[3] - 1
d <- data.frame(das = rep(2:(nd + 1) + trl$das0 - 1, 3), rmse = c(err_by_day(cvl$pred), err_by_day(cvs$pred), err_by_day(lk)),
                model = factor(rep(c("cubic polynomial", "B-spline in TT", "no-weather lookup"), each = nd), c("cubic polynomial", "B-spline in TT", "no-weather lookup")))
d <- d[d$das <= 15 + 140, ]
ggplot(d, aes(das, rmse, colour = model)) + geom_line(linewidth = 0.9) +
  scale_colour_manual(values = unname(dgxe[c("red", "green", "blue")])) + labs(x = "days after sowing", y = "held-out LAI RMSE", colour = NULL) + theme_dgxe()
ImportantPitfall

The spline library is far better than the polynomial for LAI (0.53 versus 0.89 trajectory RMSE) and beats the lookup at day 113 and at maturity, but over whole trajectories the lookup is still slightly ahead (0.47). The polynomial is clearly worse than the lookup everywhere. A polynomial in standardised drivers cannot make the rise-and-fall shape of LAI. When a model fails, look at the library before the fitting method: a better regression cannot find a term that is not in the dictionary.

2 · Collinear drivers: stable curves, unstable coefficients

Thermal time and day length move together (correlation 0.97). Fit the same model separately on the odd and even years and compare.

odd <- which(tr$years %% 2 == 1); even <- which(tr$years %% 2 == 0)
fo <- fit_years(gram, odd, fit_ols); fe <- fit_years(gram, even, fit_ols)
tab <- round(cbind(odd_years = fo$mu, even_years = fe$mu), 3); rownames(tab) <- gram$names; tab[c("TT", "TT^2", "DL", "DL^2"), ]
     odd_years even_years
TT      -0.063     -0.037
TT^2    -0.036     -0.031
DL       0.045      0.020
DL^2    -0.055     -0.051

The coefficients for TT and DL are quite different between the halves. But what matters is the growth rate the model predicts:

Tbar <- apply(Theta, c(2, 3), mean)
r_odd <- as.vector(Tbar %*% fo$mu); r_even <- as.vector(Tbar %*% fe$mu)
c(correlation = cor(r_odd, r_even), max_difference_t_per_ha_day = max(abs(r_odd - r_even)))
                correlation max_difference_t_per_ha_day 
                0.998197498                 0.009107564
NoteIdea

When drivers are collinear, the data constrain the combination, not each coefficient. The predicted rate is stable; individual coefficients are not. That is why step 6 reads curves, never single coefficients, and why a sparse model’s choice between TT and DL should not be over-interpreted.

3 · Small daily errors, large accumulated errors

The regression is on daily increments. The prediction is a running total of those increments, so small biases add up.

cv <- cv_blocked(Theta, tr, gram, fit_ssr, k = 12)
inc_err <- numeric(0)
for (g in seq_along(tr$genotypes)) for (y in seq_along(tr$years)) { n <- tr$nend[g, y]
  inc_err <- c(inc_err, diff(cv$pred[g, y, 1:(n + 1)]) - diff(tr$Y[g, y, 1:(n + 1)])) }
c(daily_increment_rmse = sqrt(mean(inc_err^2)), rollout_rmse = unname(evaluate(cv$pred, tr)[1]))
daily_increment_rmse         rollout_rmse 
          0.02801567           0.52096960

A tiny daily error can produce a large accumulated one, so always judge the model on the rollout, never on one-step fit.

A checklist before you trust a result

Question How to check
Did you validate on years the model never saw? leave-one-year-out (step 5)
Does it beat a no-weather lookup? step 5 and step 7 baselines
Is the library able to express the target? plot predicted versus APSIM trajectories; try a richer library
Is the choice between sparse terms stable? compare fits on halves of the years
Do the curves make agronomic sense? accumulated local effects (step 6)
